¿Qué es y para qué sirve?

Este conector permite a flujos y agentes de Ruvic gestionar el ciclo de vida de credenciales de infraestructura en HashiCorp Vault, sin guardar secretos en el workflow: lectura y escritura KV, emisión de credenciales dinámicas (AWS, Azure, GCP, base de datos y SSH), rotación y revocación de leases.

No configura mounts ni políticas de Vault. Usa un motor y una política que ya existen, con AppRole (recomendado) o token.

Prerrequisitos

  • Cluster Vault accesible desde Ruvic por HTTPS (TLS válido).
  • KV v1 o v2 montado (por defecto secret).
  • Motores dinámicos montados solo si vas a usarlos: aws, azure, gcp, database, ssh.
  • Método de autenticación AppRole habilitado, o un token no-root con TTL y políticas mínimas.
  • Namespace de Vault Enterprise, si aplica.

Configuración en el fabricante

  1. Crear una política mínima: Define capabilities solo sobre los paths que Ruvic debe usar. Ejemplo KV v2 + leases:
path "secret/data/infra/*" {
  capabilities = ["create", "read", "update", "patch", "delete"]
}
path "secret/metadata/infra/*" {
  capabilities = ["read", "list", "update", "delete"]
}
path "secret/delete/infra/*" {
  capabilities = ["update"]
}
path "secret/undelete/infra/*" {
  capabilities = ["update"]
}
path "sys/leases/lookup" {
  capabilities = ["update"]
}
path "sys/leases/renew" {
  capabilities = ["update"]
}
path "sys/leases/revoke" {
  capabilities = ["update"]
}
  1. Habilitar AppRole: Monta approle, crea un rol ligado a la política y genera Role ID + Secret ID. No uses el token root en Ruvic.
  2. Preparar motores dinámicos: Configura roles de AWS/Azure/GCP/database/SSH en Vault (no en Ruvic). El conector solo llama a creds, sts, sign, rotate-role y rotate-root.
  3. Comprobar conectividad: Desde un entorno de confianza, verifica /v1/sys/health y un login AppRole antes de guardar la credencial en Ruvic.

Permisos requeridos

Permiso (path Vault) Para qué sirve
auth/approle/login Autenticación de máquina. El conector no persiste el client token.
secret/data/* y secret/metadata/* CRUD y listado de secretos estáticos de infraestructura (KV v2).
database/creds/<rol>, rotate-role/*, rotate-root/* Emitir y rotar credenciales de base de datos.
ssh/creds/*, ssh/sign/*, ssh/issue/* OTP, firma de certificados y emisión de claves SSH.
aws/creds/*, aws/sts/*, aws/config/rotate-root Credenciales IAM/STS de corta duración y rotación de root AWS.
azure/creds/*, azure/rotate-root Service principals de Azure y rotación de root.
gcp/roleset/*/token, gcp/config/rotate-root Tokens o keys de GCP y rotación de root.
sys/leases/lookup, renew, revoke Consultar, renovar y revocar leases. No se exponen revoke-prefix ni revoke-force.

Configuración en Ruvic

  1. Crear credencial: HashiCorp Vault API. URL del cluster, AppRole (Role ID + Secret ID) o token, namespace opcional, mounts KV/AWS/Azure/GCP/database/SSH.
  2. Probar conexión: Ruvic hace login y auth/token/lookup-self. El token no se muestra en la UI.
  3. Añadir el nodo: Elige recurso (KV, Lease, Database, SSH, AWS, Azure, GCP, System) y operación. Activa «Mask secret values» salvo que el siguiente paso necesite el secreto en claro.
  4. Rotación KV: KV no rota solo. La operación Rotate escribe una versión nueva (CAS opcional). Para secretos dinámicos usa Rotate Role / Rotate Root del motor.

TLS permanece activo. «Ignore SSL issues» solo para laboratorios aislados.

Verificación

  1. Test connection de la credencial en verde.
  2. System → Health responde; Lookup Self no incluye el id del token.
  3. KV Read de un path de prueba y List del prefijo.
  4. Si hay motor dinámico: Generate credentials, anota lease_id, Lease → Revoke y confirma que ya no autentica.

Solución de problemas

Síntoma Causa probable
403 / permission denied La política no cubre el path (en KV v2 el listado va por metadata/, no por data/).
404 en KV Mount o versión KV incorrectos (v1 vs v2), o el path no existe.
Fallo de AppRole Role ID/Secret ID inválidos, mount distinto de approle, o Secret ID de un solo uso ya consumido.
Error TLS Certificado no confiable. Corrige la CA; no desactives TLS en producción.
Revoke no invalida El secreto era KV (sin lease) o el rol no es renewable. Revoke solo aplica a credenciales dinámicas.

Preguntas frecuentes y notas de seguridad

¿Ruvic almacena los secretos que lee de Vault?

No. El conector autentica, llama a la API y devuelve el JSON al paso del flujo. Activa el enmascarado para que passwords y tokens no queden visibles en la ejecución.

¿Por qué no hay revoke-force?

Es una operación sudo peligrosa. El conector solo ofrece lookup, renew y revoke sincrónico de un lease concreto.

¿Cómo se rotan secretos KV?

Escribiendo una versión nueva (operación Rotate/Write). Vault no rota KV por sí mismo. Los motores dinámicos sí tienen rotate-root y rotate-role.

¿Puedo usar un token root?

No se recomienda. Usa AppRole con Secret ID wrapping o periódico y una política de mínimo privilegio.

Nunca pidas a un agente «devuélveme todas las credenciales». Limita paths y desactiva operaciones de escritura/rotación si el bot solo debe leer.
